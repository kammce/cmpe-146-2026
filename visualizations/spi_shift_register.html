How it works

Parallel load. Clicking "Parallel Load" copies all 8 bits of the staged byte into the controller's shift register at once, on its 8 parallel input pins (D7…D0) — this is what a real PISO chip's load control does, and it's instantaneous; no clock is involved yet.

Shifting out (PISO). Each clock edge (Step), exactly one bit — always the current MSB, bit7 — leaves the controller's register onto COPI, and the whole register shifts left by one position, backfilling the vacated bit0 slot with 0. After 8 clocks the controller's register is entirely zeroed out: every bit it had has been shifted out, most-significant bit first.

Shifting in (SIPO). The peripheral has no parallel input pins at all — only a single serial-in wire. Each clock edge, the bit arriving on that wire enters at bit0 and the whole register shifts left, pushing everything already there one position toward bit7. The very first bit received (the controller's original bit7) gets pushed all the way to the peripheral's bit7 by the time all 8 clocks are done, while the last bit received (the controller's original bit0) is still sitting in bit0, untouched by any further shift. The two ends land exactly where they should, and the peripheral's register now holds the identical byte — available on its 8 parallel output pins, Q7…Q0, with no more clocking needed.

Real SPI hardware actually shifts data in both directions on the very same clock edges — COPI and CIPO are independent wires, so the controller is simultaneously receiving on its own SIPO half while the peripheral is simultaneously transmitting on its own PISO half. This page isolates just one direction to make the shift-register mechanic itself easy to follow; the SPI Bus Visualizer shows the full duplex picture together with chip-select and command semantics.
