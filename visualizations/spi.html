How it works
Assert CS, then Write [0xC1, 0xA5] (command 0xC1 = read-back, address 0xA5) — the sensor recognizes this exact 2-byte sequence and arms itself. While CS stays asserted, pressing Read then clocks out the 2-byte temperature on CIPO (signed 16-bit, 0.01°C per LSB, MSB first). The sensor only answers once per chip-select session: reading again right after returns nothing, and it can't be re-armed by writing the command again either — releasing and re-asserting CS resets it, so a fresh session always gets a fresh answer. Any other command, or releasing CS before reading, disarms the sensor too. Write and Read both work even with CS released — the controller still clocks bytes onto the bus, but an unselected sensor ignores them completely, exactly like real hardware. The simulated temperature drifts slowly on its own unless you check Override, which freezes it at whatever value you type. SPI Mode controls when data is sampled/shifted relative to the clock edge (CPOL/CPHA) — try switching modes and watch the COPI/CIPO edges move relative to SCK. Use Graph Zoom to widen individual clock edges, and watch the MCU/ sensor schematic above — each wire glows when it's electrically HIGH, except CS, which glows when it's asserted (active-low).
