How it works

Shared bus, two chip selects. Both devices sit on the same SCK, COPI, and CIPO wires, but each has its own CS line (the schematic above shows both). Only one CS is ever asserted at a time — that's what "Target Device" picks — and the controller can't switch devices while a CS is held low. An unselected device sees the same SCK/COPI clocking as everyone else, but ignores it completely and never drives CIPO, exactly like real multi-drop SPI.

Temp Sensor. Assert its CS, then Write [0xC1, 0xA5] (command 0xC1 = read-back, address 0xA5) — the sensor recognizes this exact 2-byte sequence and arms itself. While CS stays asserted, pressing Read then clocks out the 2-byte temperature on CIPO (signed 16-bit, 0.01°C per LSB, MSB first). The sensor only answers once per chip-select session: reading again returns nothing, and re-arming needs a fresh release/re-assert of its CS. The simulated temperature drifts slowly on its own unless you check Override.

GPIO Expander. A much simpler device: an 8-bit output register that persists forever (it does not reset when its CS is released, unlike the sensor's one-shot arm state). Write [0x50, value] to set all 8 outputs at once — watch the LEDs on its chip and in the devices panel update immediately. Write [0x51] to arm it, then Read 1 byte to shift the current register value back out on CIPO — it can be armed and read repeatedly within one CS session, no release needed. To flip just one bit without disturbing the others, use "Toggle Bit": it scripts the real read-modify-write sequence a driver would run — Read the current output, flip one bit in software, then Write the whole byte back — and you can watch all three transfers happen back to back on the trace.

SPI Mode controls when data is sampled/shifted relative to the clock edge (CPOL/CPHA) — try switching modes and watch the COPI/CIPO edges move relative to SCK. Use Graph Zoom to widen individual clock edges.
